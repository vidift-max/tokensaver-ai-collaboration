CORREÇÃO TÉCNICA DO PROJETO BLOGGER CANNIBALIZATION AI

Você está trabalhando em um projeto já existente. Sua missão é investigar, corrigir e testar o problema de autenticação com Google, preservando toda a estrutura e as configurações que já foram realizadas.

IMPORTANTE: NÃO comece um projeto novo. NÃO apague arquivos. NÃO substitua a aplicação inteira. Primeiro investigue o código existente e identifique a causa real do problema.

1. Identificação do projeto

Nome: Blogger Cannibalization AI

Repositório GitHub:
https://github.com/vidift-max/blogger-cannibalization-mcp

Branch utilizada no Render:
"v2-saas-alpha"

Serviço MCP no Render:
https://blogger-cannibalization-mcp.onrender.com

Aplicação principal:
https://blogger-cannibalization-ai.onrender.com

Banco de dados PostgreSQL:
"blogger-cannibalization-ai-db"

Projeto Google Cloud:
Blogger API v3

Conta Google de teste:
vidift@gmail.com

2. Situação atual

O projeto já foi configurado e publicado no Render.

As configurações de autenticação Google já foram realizadas, incluindo:

- Criação do cliente OAuth Web.
- Configuração do Client ID.
- Configuração do Client Secret no ambiente do Render.
- Configuração do usuário como testador no Google Cloud.
- Configuração da URL de redirecionamento.
- Configuração da conexão PostgreSQL.
- Configuração da variável GOOGLE_REDIRECT_URI.
- Configuração da variável TOKEN_ENCRYPTION_KEY.

O serviço MCP inicia e aparece como Live no Render.

O login com Google, porém, ainda não funciona.

3. Erro atual

Ao acessar a aplicação e clicar em Entrar com Google, o usuário seleciona sua conta Google e retorna para o endereço do serviço MCP.

A página apresenta:

"Autorização Google inválida. Tente conectar novamente."

Esse erro acontece no retorno do Google, durante a validação do OAuth.

4. Endereço de callback configurado

O endereço configurado no Google Cloud é:

"https://blogger-cannibalization-mcp.onrender.com/api/oauth/google/callback"

O código existente utiliza:

- "src/routes.js"
- "src/index.js"
- "src/blogger.js"
- "src/security.js"

O arquivo "src/index.js" monta as rotas com:

"app.use('/api', router);"

O arquivo "src/routes.js" possui:

"router.get('/auth/google', ...)"

e:

"router.get('/oauth/google/callback', ...)"

Portanto, o callback esperado é:

"/api/oauth/google/callback"

5. O que você deve investigar

Faça uma revisão técnica completa do fluxo OAuth, principalmente:

1. Verifique como o nonce é gerado no início do login.
2. Verifique como o cookie "oauth_nonce" é criado.
3. Verifique se o cookie está sendo realmente enviado pelo navegador ao retornar do Google.
4. Verifique as configurações "secure", "sameSite", "path", domínio e expiração do cookie.
5. Verifique o funcionamento do "cookie-parser".
6. Verifique se o valor "state" devolvido pelo Google corresponde ao nonce armazenado no cookie.
7. Verifique se existe alguma diferença de domínio entre a aplicação principal e o serviço MCP.
8. Verifique se o fluxo de redirecionamento entre os dois serviços está correto.
9. Verifique se o endereço de callback utilizado pelo código corresponde exatamente ao endereço autorizado no Google Cloud.
10. Verifique se há algum problema de sessão, proxy HTTPS ou configuração do Render.

Não presuma que o problema está nas credenciais. O erro atual ocorre na validação da autorização e precisa ser investigado com evidências.

6. Verifique também as variáveis de ambiente

Confira se o código utiliza corretamente estas variáveis:

- GOOGLE_CLIENT_ID
- GOOGLE_CLIENT_SECRET
- GOOGLE_REDIRECT_URI
- DATABASE_URL
- TOKEN_ENCRYPTION_KEY
- COOKIE_SECURE

Não exponha os valores secretos.

Não altere as credenciais sem necessidade.

Não gere uma nova TOKEN_ENCRYPTION_KEY, pois já existe uma configurada e a troca pode impedir a descriptografia dos tokens armazenados.

Se alguma variável estiver ausente, informe apenas o nome dela e explique onde configurá-la.

7. Correção do código

Depois de identificar a causa:

- Corrija somente os arquivos necessários.
- Preserve as funcionalidades existentes.
- Preserve a conexão com PostgreSQL.
- Preserve a estrutura atual do projeto.
- Preserve a integração com a API do Blogger.
- Não remova os mecanismos de segurança.
- Não desative a validação do state como solução improvisada.
- Não coloque segredos diretamente no código.
- Não altere o callback autorizado sem justificar tecnicamente a necessidade.

Se houver necessidade de modificar o código, faça a alteração na branch "v2-saas-alpha".

8. Testes obrigatórios

Depois da correção, verifique:

1. Se o serviço inicia sem erros.
2. Se o endpoint "/healthz" responde corretamente.
3. Se o login com Google inicia.
4. Se o cookie de segurança é criado.
5. Se o callback recebe e valida corretamente o state.
6. Se o Google retorna os tokens.
7. Se o usuário é identificado.
8. Se os tokens são armazenados de forma criptografada.
9. Se a sessão é criada.
10. Se a aplicação consegue carregar os blogs da conta Google.

Não considere o trabalho concluído apenas porque o deploy foi bem-sucedido. O login precisa funcionar de verdade.

9. Outros problemas conhecidos

Em logs anteriores também apareceu um erro de sincronização:

"HTTP 404 em https://blogger-cannibalization-ai.onrender.com/feeds/posts/default?max-results=25&start-index=1"

Esse problema pode estar relacionado à integração ou à inicialização da sincronização com o Blogger.

Investigue separadamente, sem misturar esse problema com o erro atual de OAuth.

10. Como quero receber o resultado

Trabalhe como um engenheiro de software responsável pelo projeto.

Antes de alterar qualquer coisa, apresente:

- A causa provável do erro.
- Os arquivos que precisam ser corrigidos.
- O plano de correção.

Depois faça a correção e os testes.

Ao terminar, apresente:

- Arquivos modificados.
- Resumo das alterações.
- Resultado dos testes.
- Se é necessário fazer alguma alteração no Render.
- Se é necessário fazer alguma alteração no Google Cloud.
- Qual é o próximo passo para testar o login.

Não peça ao proprietário para enviar senhas, chaves privadas, Client Secret, DATABASE_URL ou TOKEN_ENCRYPTION_KEY. Trabalhe com o código e com os nomes das variáveis de ambiente.

O objetivo final é entregar o Blogger Cannibalization AI funcionando, com login Google, conexão com Blogger, listagem de blogs e análise de possíveis conflitos entre artigos.

src/security.js (completo)
JavaScript
import crypto from 'node:crypto';

export function randomToken(bytes = 32) {
  return crypto.randomBytes(bytes).toString('base64url');
}

export function safeEqual(a, b) {
  const ba = Buffer.from(String(a || ''), 'utf8');
  const bb = Buffer.from(String(b || ''), 'utf8');
  if (ba.length !== bb.length) return false;
  return crypto.timingSafeEqual(ba, bb);
}

export function hashToken(value) {
  return crypto.createHash('sha256').update(String(value)).digest('hex');
}

const STATE_TTL_MS = 10 * 60 * 1000; // 10 min — mesmo prazo do nonce anterior

function stateKey() {
  // Preferencia: segredo dedicado. Fallback: a chave de criptografia ja existente.
  // Nao e usado para descriptografar tokens do banco, apenas para assinar state.
  return process.env.OAUTH_STATE_SECRET || process.env.TOKEN_ENCRYPTION_KEY || '';
}

function hmac(value) {
  return crypto.createHmac('sha256', stateKey()).update(value).digest('base64url');
}

/** state = nonce.timestamp.assinatura — validavel sem cookie, CSRF-safe. */
export function createState() {
  const nonce = randomToken(24);
  const ts = Date.now().toString(36);
  return `${nonce}.${ts}.${hmac(`${nonce}.${ts}`)}`;
}

/** Retorna true se o state tem assinatura valida e prazo valido (10 min). */
export function verifyState(state) {
  if (typeof state !== 'string') return false;
  const parts = state.split('.');
  // base64url nao contem '.', entao sao exatamente 3 partes
  if (parts.length !== 3) return false;
  const [nonce, ts, sig] = parts;
  if (!safeEqual(sig, hmac(`${nonce}.${ts}`))) return false;
  const t = parseInt(ts, 36);
  if (!Number.isFinite(t)) return false;
  if (Date.now() - t > STATE_TTL_MS) return false;
  return true;
}

export function tokenize(text) {
  return (String(text || '').toLowerCase().match(/[a-z][a-z0-9'-]+/g) || [])

    .map((w) => w.replace(/'(s|t|re|ve|ll|d)$/, ''))

const ngrams = (tokens, n) =>

export function extractKeywords(text, topN = 12) {
  const tokens = tokenize(text);
  const freq = {};
  for (const g of [...ngrams(tokens, 1), ...ngrams(tokens, 2), ...ngrams(tokens, 3)]) {
    freq[g] = (freq[g] || 0) + (g.includes(' ') ? 2 : 1);
  }
  return Object.entries(freq)
    .filter(([k]) => !((k.includes(' ') === false) && tokens.filter((t) => t === k).length < 2))
    .sort((a, b) => b[1] - a[1])
    .slice(0, topN)
    .map(([k]) => k);
}

export function buildIndex(articles) {
  const docs = articles.map((a) => ({
    id: a.id, title: a.title, url: a.url, labels: a.labels || [], keywords: a.keywords || [],
    tokens: [
      ...tokenize(a.title), ...tokenize(a.title), ...tokenize(a.title), // título pesa 3x

  const N = Math.max(docs.length, 1);
  const idf = {};
  for (const [t, n] of Object.entries(df)) idf[t] = Math.log(1 + N / n);
  const vectors = docs.map((d) => {
    const tf = {};
    for (const t of d.tokens) tf[t] = (tf[t] || 0) + 1;
    const v = {};
    for (const [t, c] of Object.entries(tf)) v[t] = c * (idf[t] || 0);
    return { ...d, vector: v, norm: Math.sqrt(Object.values(v).reduce((s, x) => s + x * x, 0)) || 1 };
  });
  return {
    vectors, idf, N,
    vectorize(text) {
      const tokens = tokenize(text);
      const tf = {};
      for (const t of tokens) tf[t] = (tf[t] || 0) + 1;
      const v = {};
      for (const [t, c] of Object.entries(tf)) v[t] = c * (idf[t] || 0);
      return { vector: v, norm: Math.sqrt(Object.values(v).reduce((s, x) => s + x * x, 0)) || 1 };
    },
  };
}
